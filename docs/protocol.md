# Протокол пульта SmartTV (v1)

Этот протокол используют тестовый веб-пульт (`desktop/src/remote-web`) и будущее Android-приложение.

## Транспорт

| Что | Где |
|---|---|
| WebSocket | `ws://<IP-компьютера>:8765/ws` (если порт 8765 занят, берётся следующий: 8766…8774) |
| Веб-пульт | `http://<IP>:8765/` |
| Поиск ПК в сети | UDP-широковещание на порт **8766** |

Все сообщения — JSON-объекты в текстовых кадрах, не больше 64 КБ.

Если браузер присылает заголовок `Origin`, он должен совпадать с `Host`: чужие сайты на телефоне подключиться не смогут. Нативное приложение `Origin` не отправляет.

## Поиск ПК (discovery)

Клиент шлёт UDP-пакет с текстом `SMARTTV_DISCOVER` на `255.255.255.255:8766`. Каждый ПК со SmartTV отвечает на адрес отправителя:

```json
{ "service": "smarttv", "name": "SmartTV", "id": "a1b2c3d4e5f6", "port": 8765, "version": 1 }
```

`id` постоянен для компьютера. Пульт сохраняет его, чтобы найти ПК снова, когда сменится IP.

## QR-код

На экране «Подключить пульт» показан QR с адресом:

```
http://192.168.1.12:8765/#pair=1234
```

Хост и порт берутся из URL, PIN — из фрагмента `#pair=`. Android-приложение разбирает эту же строку.

## Подключение

1. После соединения сервер сразу шлёт:
   ```json
   { "type": "hello", "name": "SmartTV", "id": "a1b2c3d4e5f6", "version": 1, "pairingRequired": true }
   ```
2. **Первое подключение**, по PIN с экрана:
   ```json
   → { "type": "pair", "pin": "1234", "name": "Pixel 8" }
   ← { "type": "paired", "token": "<секрет>", "deviceId": "9f8e7d6c5b4a" }
   ← { "type": "authed", "deviceId": "9f8e7d6c5b4a", "name": "SmartTV" }
   ```
   Токен нужно сохранить: при следующих подключениях PIN уже не нужен. После каждого успешного сопряжения PIN на экране меняется. После 5 неверных попыток тоже.
3. **Повторное подключение:**
   ```json
   → { "type": "auth", "token": "<секрет>" }
   ← { "type": "authed", ... }
   ```
   Если пульт отвязали на ПК, придёт `{ "type": "error", "code": "bad_token" }`. Токен надо удалить и снова запросить PIN.

После `authed` сервер присылает текущее состояние `state`. Дальше он рассылает его при каждом изменении экрана.

## Команды пульта

| Команда | Пример |
|---|---|
| Кнопка | `{ "type": "key", "key": "up" }` |
| Текст в поле ввода | `{ "type": "text", "text": "котики" }` |
| Мышь (сдвиг в пикселях) | `{ "type": "mouse", "dx": 12, "dy": -4 }` |
| Клик | `{ "type": "click", "button": "left" }` (или `"right"`) |
| Колесо | `{ "type": "scroll", "dy": -120 }` (120 = один щелчок колеса, минус = вниз) |
| Громкость Windows | `{ "type": "volume", "action": "up" }` (`up`, `down`, `mute`) |
| Открыть ссылку | `{ "type": "open", "url": "https://youtu.be/dQw4w9WgXcQ" }` |
| Запросить состояние | `{ "type": "getState" }` |
| Проверка связи | `{ "type": "ping" }` → `{ "type": "pong" }` |

Значения `key`: `up`, `down`, `left`, `right`, `ok`, `back`, `home`, `playpause`, `seekfwd`, `seekback`, `backspace`, `enter`.

Ссылки YouTube (`youtu.be`, `watch?v=`, `shorts/`) открываются в ТВ-версии YouTube, остальные — как обычный сайт.

## Сообщения от ПК

```json
{ "type": "state", "screen": "home|player|service", "title": "YouTube", "tvMode": true }
{ "type": "error", "code": "unauthorized|bad_pin|bad_token|bad_url|load_failed", "message": "Текст для пользователя" }
```

Каждые 15 секунд сервер шлёт WebSocket-ping. Клиенты, которые не ответили, отключаются.
